For Java, .NET and PHP systems

Move legacy systems to a current platform, and prove they still work.

Renova assesses an old codebase, migrates a copy of it, builds the result, runs its tests and compares its behaviour with the original. Rules do the mechanical bulk; AI on your own key handles what needs judgement; a report lists exactly what is left.

What it migrates

Three ecosystems, one way of working

Every path is a playbook of rules. Pick the target; Renova finds what has to change and says how much of it needs no human decision.

Java

Java 8 and Java EE to Java 21 and beyond

  • Java 8, 11, 17 → 17, 21 or 25
  • javax → Jakarta EE 10 and 11
  • Spring Boot 2 → 3.5 and 4.1; Spring Framework 7
  • Java EE on an application server → Spring Boot
  • Micronaut 4, Quarkus 3, Hibernate 6 and 7, Struts 7
  • Maven, Gradle and Ant builds; Kotlin sources
.NET

.NET Framework to .NET 8 or 10

  • C# and Visual Basic, old project format → SDK style
  • packages.config → package references
  • NUnit 2 → 3; MSTest and xUnit made runnable
  • WCF services hosted by IIS → CoreWCF
  • ASP.NET MVC 5 and Web API 2 → ASP.NET Core, with AI
  • Windows Forms and WPF projects converted
PHP

PHP 5 and 7 to PHP 8.3, 8.4 or 8.5

  • Removed functions and syntax rewritten by Rector
  • Laravel 7 to 10 → Laravel 11, 12 or 13
  • Symfony 4 to 7 → 6.4, 7.4 or 8.1
  • Sites without Composer get one
  • Plain PHP sites moved inside Laravel 13
  • PHPUnit brought to a release that runs

The full list, with what has been run and what has not, is in verified migrations.

How it works

Assess first. Change a copy. Check everything.

The same five steps whether you start from the desktop app, a terminal, your editor or a CI pipeline.

Assess

A read-only scan lists every place that has to change, by category and severity, with an automation rate.

Plan

Findings become ordered steps: build and dependencies first, behaviour-sensitive changes last.

Migrate

Syntax-aware rewrites and rules run on a copy. Each stage is one git commit you can review or revert.

Verify

The migrated project is built and its own tests run. Failures feed an AI repair loop; tests are never bent to pass.

Compare

The original and the result run side by side in containers and answer the same requests. Differences are reported.

Why teams choose it

Built for code that cannot leave the building

Your source is never touched

Renova works on a copy in a workspace of its own. The project you point it at is read, never written.

Runs on your machine

The desktop app needs no server, no account and no open port. Code and migrated copies stay on the device.

Your own AI key

AI steps use your Anthropic or OpenAI account. Only those requests leave the machine, and token use is reported per migration.

Migrations are data

A migration path is a YAML playbook. Add your own conventions or a new target without changing the engine.

Verified, not assumed

A migration ends with a build result, a test result and, for web applications, a request-by-request comparison.

An honest report

What changed, stage by stage, and what is left for a person, written like a migration guide you can hand to a reviewer.
