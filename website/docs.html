Documentation

Enough to install Renova and run a first migration. The complete reference lives beside the code on GitHub.

Your first assessment

  1. Download and install the desktop app.
  2. Choose Add project and pick the folder that holds the project's pom.xml, build.gradle, build.xml, .sln, composer.json or index.php.
  3. Read the assessment: what was found, by category and severity, and the share that needs no human decision.
  4. Choose a target and an empty folder for the migrated copy, then start the migration.

The project you added is only read. Everything Renova writes goes into the folder you chose, as a git repository with one commit per stage and a report in .renova/report.md.

Desktop app

The installer carries its own Java runtime. Projects, settings and results are kept on your device; there is no server and no account.

SystemInstall
WindowsRun the .msi. SmartScreen warns because the installer is not signed yet: More info → Run anyway.
macOSTake the installer for your Mac: Apple Silicon (M1 and later) or Intel; Apple menu → About This Mac says which. Open the .dmg and drag Renova to Applications. The first time, right-click the app and choose Open.

Any other LinuxUnpack the .tar.gz anywhere and run Renova/bin/Renova. Nothing is installed; delete the folder to remove it.

Settings hold the AI provider and key, the licence, and where JDKs, the .NET SDK and PHP are found if not in the usual places.

Command line

Unzip renova-cli-*.zip and put its bin folder on your PATH. It needs Java 21 or later, whatever language the project is written in.

# What can be migrated, and to what
renova playbooks

# Assess a project: read-only. Markdown by default, JSON for tooling
renova analyze /path/to/project
renova analyze /path/to/project -f json -o assessment.json

# Rank every project under a folder, easiest first
renova portfolio /path/to/all-projects -f csv -o portfolio.csv

# Migrate a copy into an empty folder
renova migrate /path/to/project --out /path/to/migrated -p java8-to-21-jakarta-ee10

# With an add-on, and comparing behaviour with the original
renova migrate /path/to/project --out /path/to/migrated -p dotnet-to-10+efcore --verify-behaviour

migrate exits with 0 when the migrated build passes (and, with --verify-behaviour, the application behaves the same), 1 otherwise and 2 on a usage error, so a pipeline can gate on it. Useful options: --ai none to run without AI, --skip-tests to only compile, --offline for Maven, --max-ai-iterations for the number of repair rounds.

VS Code and IntelliJ

VS Code

Install the .vsix with Extensions: Install from VSIX…. Open a folder with a project in it and run Renova: Assess Workspace. Findings appear as diagnostics and in the Renova view, each with who resolves it: a rule, AI checked by the build, or a person. Renova: Migrate… writes a migrated copy to a folder you choose.

IntelliJ IDEA

In Settings → Plugins choose the gear, then Install Plugin from Disk… and pick the zip. It needs IntelliJ IDEA 2025.2 or later. The Renova tool window shows the assessment and the plan, and starts migrations.

Both use the same settings file as the CLI and the desktop app, so the AI key and the licence are set once.

Web console

The web bundle is the API and a browser console in one archive. It needs Java 21 and Node.js 20.

tar -xzf renova-web-*.tar.gz && cd renova-web-*
bin/renova-web local      # one person, this machine only, no sign-in
bin/renova-web            # a team: accounts, organisations, roles, audit log

On a server, people sign in with a password or through your identity provider over OpenID Connect (Entra ID, Okta, Google Workspace, Keycloak). The bundle's README covers systemd, HTTPS behind a reverse proxy, backup and upgrade; single sign-on is described in the deployment guide.

AI on your own key

Most of a migration needs no AI. Where a change needs judgement (a framework with no successor release, behaviour that differs on the new platform, a build error no rule explains), Renova sends that code to the provider you configure, applies the answer and lets the build decide whether it stands.

  • Set the provider and key in the desktop app's settings, or with renova config. Anthropic and OpenAI are supported.
  • The key is yours; requests go from your machine to your provider. Token use is reported per migration.
  • Without a key, AI steps are listed in the report as work for a person.
  • Tests are never edited to make them pass.

Comparing behaviour

With --verify-behaviour (a switch in the apps), after the build passes Renova starts the original and the migrated application in containers, sends both the same requests and compares status, redirect, content type and body. It needs Docker.

Requests are found from the code. For forms, query strings and sequences, add a renova-scenarios.yaml to the project:

scenarios:
  - id: book-and-read
    steps:
      - {{ method: POST, path: /new.php, form: {{ patient: "Yaw Boakye", day: "2024-03-11" }} }}
      - {{ path: "/view.php?id=4" }}

Licences

Assessing is free. Everything up to starting a migration works without a licence, so you can see what Renova finds in your own code first.

Migrating needs a licence file that covers the project's ecosystem. The file is signed; Renova checks the signature on your machine and sends nothing anywhere, so it works without internet access.

renova licence install acme.json   # make this file the machine's licence
renova licence                     # what is installed and what it allows

In the desktop app: Settings → Licence → Install licence file…. On a server or build agent, set RENOVA_LICENCE to the file's path. To ask for a licence or a trial, open a request.
